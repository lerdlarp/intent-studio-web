# Golden data

Output of the original C# Intent Studio model (WarpDesigner `feature/VisualAiAssistant` @ a2029574) on its four demo
rooms. Generated by `GoldenDump.cs.txt` (a throwaway MSTest), run twice with byte-identical results. Units: feet, footcandles.
JSON is camelCase; `P2` points are `{x, y}`; enums are strings.

| File | Contents |
|---|---|
| `Office.json`, `Cafeteria.json`, `Lobby.json`, `DataHall.json` | `room` (full input + derived `spaceClass`, `spaceTypeWords`, `wallNames`, `clusters`), `seeds` (`IntentSuggestions.Seed`, before solving), `fallbackAdvice` (`FallbackStudioAi.Advise` on the seeds), `solved` (all seeds accepted, then `IntentSolver.SolveAll`: product, fixtures, trace, `QuickEstimate` per intent), `power`, `probes` (`QuickEstimate.At` on a 2.5 ft plane at four diagonal points), `interpret` (`StudioInterpreter.Interpret` on fixed phrases) |
| `misc.json` | beam → cosⁿ exponent, every generic lumen package, feet-inches formatting, `ClassFromWords` cases |

Intent and fixture ids are random in the original, so intents are identified by `index` (order) and fixtures are
compared as an ordered list.

## How the port must use it

- **Exact:** space class, labels, target ranges and reasons, planes, seed order and regions, interpreter intents, product
  family and lumen package per solved intent, fixture **count** per intent, mount strings, `feetInches`, `classFromWords`.
- **Tolerance 1e-6 ft:** region and fixture coordinates, heights.
- **Tolerance 1e-6 relative:** exponents, estimates (average/min/max), probes, watts, LPD.
- Trace lines: exact text is the goal; if a number formats differently (C# `0.#`, `#,0` formats), fix the formatter, not the test.

If a mismatch comes from a deliberate web-version change (e.g. adding CCT), regenerate expectations in TypeScript and
record the reason in `handoff/PROGRESS.md`; never silently loosen a tolerance.

Note: several solved intents land above their target (e.g. the lobby path at ~23 fc against 3 fc) because other intents'
light already falls on that plane; the trace says so. That is the reference behaviour, not a bug to fix during the port.
